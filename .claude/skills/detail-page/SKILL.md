# 상세페이지: 재료 → 기획 → 디자인 → HTML 한 파일

**기본은 묻지 않고 끝까지 간다.** 멈춤 조건일 때만 묻고, 정한 것은 `작업.md` 「5. 기록」에 남긴다. 규격 · 기본값은 `works/detail-page/CLAUDE.md`.

## 0. 작업 폴더
- 이어서 하는 일이면 그 폴더 `작업.md`부터 읽는다.
- 새 일이면 `npm run new -- detail-page "<상품>-판매" --request "<요청 원문>"`.

## 1. 재료 → 「2. 재료」
- 상품: `brand/products/<상품>.md`. 없으면 요청에서 받은 정보(가격 · 일정 · 혜택 · 링크)로 먼저 만든다.
- 내 자료: 프로필 · 후기 · 인증 · 강의 이미지 (`brand/assets/`). 대화에 첨부한 것은 먼저 거기에 저장한다.
- 레퍼런스: 채팅에 첨부 · 링크가 왔으면 **만들기 전에** `reference` 스킬 0~2 (받기 · 저장 · 패턴), 그다음 3 (연결). 쓰지 않으면 `- 레퍼런스: 없음`.

## 2. 기획 → 「3. 구성」
- 섹션 표: 순서 · 섹션 · 내용 · 근거(재료 경로).
- 카피는 내 상품 재료로 새로 쓴다. 레퍼런스 문장을 고쳐 쓰지 않는다.
- 말투는 `brand/profile.md` 「말투」.

## 3. 디자인 · 제작 (`편집/`)
- 레퍼런스 「가져올 것」(레이아웃 · 리듬 · 강조 방식) + 브랜드 색 · 폰트.
- 이미지가 필요하면 Higgsfield: 크레딧 확인 → 생성 → `편집/이미지/<번호>-<쓰임>.png`. 레퍼런스 그림체를 그대로 따라 그리게 하지 않는다.

## 4. 버전 · 검사
- `완성/v1-레퍼런스형/index.html` · `완성/v2-변형/index.html`. "그냥 두고 하나 더"는 새 폴더(`v3-웹툰형/`).
- 빌더에 올리면 `완성/<버전>/빌더용.html` (`<style>`과 본문만).
- 브라우저로 열어 모바일 폭에서 확인한다 (Claude in Chrome, 또는 사용자에게 열어 보라고).
- `npm run check -- works/detail-page/<작업>` ❌가 없을 때까지 고친다.

## 5. 마무리
- `작업.md` 「4. 버전」 · 「5. 기록」 · 상태 `완성`.
- 레퍼런스 기록은 `check`가 목록에 자동 반영한다. 사용자가 결과가 좋았다고 하면 `작업.md` 머리말 `평가: 좋음`.
- 결정 요약을 표로 보여 준다 (무엇 · 왜 · 바꾸려면).

## 멈춤 조건 (이때만 묻는다)
1. 가격 · 일정 같은 상품 정보가 재료에도 요청에도 없을 때
2. 상세페이지 레퍼런스가 하나도 없을 때 → "레퍼런스 없이 할까요, 먼저 찾을까요?"
