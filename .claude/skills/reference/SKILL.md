# 레퍼런스: 받기 → 저장 → 패턴 → 연결

레퍼런스는 **어떻게 보일지(스타일)**를 배우는 자료다. 같은 스타일의 예시 여러 개를 **묶음** 하나에 모은다.

```
references/
├── 목록.md                    자동 생성 — 손으로 고치지 않는다
└── <종류>/<묶음>/
    ├── 원본들                  영상 · 카피.md · 링크.md
    ├── 캡처/                   페이지 이미지 · 캡처 (01, 02 … 위에서 아래 순서)
    ├── 시트/ 측정.json         영상 · 이미지를 한눈에 보는 시트 (npm run reference가 만든다)
    ├── 대본/                   영상의 말을 받아 적은 것
    └── 패턴.md
```

## 0. 받기 — 자료가 들어오는 세 길
| 들어온 모양 | 할 일 |
|---|---|
| 채팅에 파일 경로가 보이는 첨부 (끌어다 놓은 파일 등) | 그 경로에서 묶음으로 **복사** |
| 채팅에 붙여 넣은 캡처처럼 경로가 없는 첨부 | 파일로 저장할 수 없다. "`inbox/`에 그 파일을 넣어 주세요"라고 한 번만 요청한다 (멈춤) |
| 링크 | 웹페이지: 아래 「웹페이지 링크」. 인스타 · 광고 영상: `링크.md`에 적고, 영상 파일은 받아서(SortFeed · AdLibNote) `inbox/`에 넣어 달라고 요청 |
| `inbox/`에 쌓인 파일 ("받은함 정리해줘") | 하나씩 종류 · 묶음을 정해 **이동**. 촬영본 · 내 사진처럼 레퍼런스가 아닌 것은 작업 `원본/`이나 `brand/<브랜드>/assets/`로. `inbox/`는 비우는 곳이다 |

### 웹페이지 링크 (상세페이지 · 펀딩 · 스토어)
1. 먼저 `npm run reference -- references/<종류>/<묶음>`으로 묶음을 만들고 `링크.md`에 주소 · 날짜를 적는다.
2. **Claude in Chrome으로 연다.** 와디즈 등은 WebFetch · 헤드리스 접속을 막는다(Access Denied). 「더보기」가 있으면 눌러 본문을 펼친다.
3. 글은 `get_page_text`로 `카피.md`. 국내 상세페이지는 본문이 대부분 **이미지**라 글이 거의 안 나온다 → 4로.
4. 본문 이미지 주소를 모은다. `javascript_tool`로 페이지를 끝까지 스크롤한 뒤 폭 300px 이상인 `img`의 주소를 페이지 순서대로 뽑는다 (예: `[...document.querySelectorAll('img')].filter(i=>i.naturalWidth>=300).map(i=>i.currentSrc||i.src)`, 중복 · 다른 상품 썸네일 · 로고는 뺀다). 한 번에 다 안 나오면 나눠서 뽑는다.
5. 주소를 한 줄에 하나씩 scratchpad의 텍스트 파일에 쓰고 → `npm run reference -- <묶음> --download <그 파일> --referer <페이지 주소>` → `캡처/01.jpg …` + `시트/이미지_*.jpg`.
6. 이미지형이면 `카피.md`에는 시트에서 읽은 **제목 · 띠 문구만** 순서대로 옮긴다 (구조를 보기 위한 것, 결과물에 쓰지 않는다).
7. 로그인이 필요하거나 이미지 주소를 못 뽑으면 사용자에게 위에서 아래로 캡처를 받아 `inbox/`로.

**만들기 요청과 함께 온 레퍼런스도 반드시 1~2를 먼저 한다.** 저장 → 패턴 → 작업에 연결한 다음 만든다.

## 1. 저장
1. 종류를 모양으로 정한다. 묻지 않는다.
   웹페이지 → `detail-page` · 세로 영상 → `reels` (광고 라이브러리에서 받은 것은 `ad-creative`) · 가로 긴 영상 → `longform` · 여러 장 이미지 → `carousel`
2. 묶음을 정한다. **`references/목록.md`부터 본다.** 같은 업종 · 스타일 묶음이 있으면 거기에 더한다. 한 번 쓰고 말 것 같아도 비슷한 묶음이 있으면 거기에 넣는다.
   - 새 묶음 이름은 `<업종>-<스타일>` (태그 목록의 말로, 예: `강의교육-증거형`, `AI정보-모션그래픽형`). 같은 이름이 있으면 `-2`.
3. `npm run reference -- references/<종류>/<묶음>` → 폴더와 `패턴.md`가 생긴다 (목록도 갱신).
4. 종류별로 넣을 것:
   | 종류 | 넣을 것 |
   |---|---|
   | detail-page | `링크.md` · `캡처/`(위에서 아래로 01, 02 …) · `카피.md`(글 전문, 이미지형이면 제목 줄만) |
   | reels · ad-creative | 영상 원본 · `대본/<영상>.md`(말을 받아 적음) |
   | longform | `링크.md` · 구간 구성 · 대본 |
   | carousel | 장별 이미지(zip은 풀어서, `캡처/`에 01, 02 …) · 장별 카피 |
5. 영상 · 이미지를 넣었으면 `npm run reference -- <같은 묶음>`을 다시 실행 → `시트/` · `측정.json` (긴 상세페이지 캡처는 이어 붙여 4칸씩, 캐러셀은 4×3 격자, GIF는 프레임 수 · 길이).

## 2. 패턴 뽑기
- 영상 · 이미지는 `시트/`를 **직접 보고**(Read) `측정.json`과 함께 판단한다. 숫자만 믿지 않는다 (부드러운 전환은 컷으로 안 잡힌다).
- 「핵심 패턴」은 묶음 전체의 공통점 **2~3개만**. 한 개에만 있는 특징은 「개별 메모」로. 많이 적으면 결과가 복사본이 된다.
- 머리말: `출처` · `태그`(`패턴.md` 안 태그 목록에서 업종 1 · 스타일 1~2 · 후킹 1) · `한줄`(핵심 패턴 한 줄).
- 묶음에 예시를 더했으면 핵심 패턴이 여전히 공통점인지 다시 본다.
- 끝나면 `npm run reference`로 목록을 갱신한다.

## 3. 연결 (작업에 쓸 때)
- 고르기: `references/목록.md`에서 고른다. 같은 종류를 먼저 보되, 다른 종류 묶음도 쓸 수 있다 (광고 묶음을 릴스에). 「좋음」 · 「쓴 작업」이 많은 묶음이 위에 있다. 후보 2~3개와 추천 하나를 말하고, 사용자가 이미 골랐으면 묻지 않는다.
- 작업 폴더 `작업.md` 「2. 재료」에 적는다:
  ```
  - 레퍼런스: `references/<종류>/<묶음>/패턴.md`
    - 가져올 것: (핵심 패턴 중 이번에 쓸 것, 구체적으로)
    - 가져오지 않을 것: 로고 · 문장 그대로 · 인물
  ```
- 레퍼런스 없이 만들기로 했으면 `- 레퍼런스: 없음` (안 적으면 `check`가 ❌).
- 버전을 둘 만들 때: v1은 가져올 것에 충실하게, v2는 같은 패턴을 다른 표현으로.

## 4. 기록
- 어떤 작업이 어떤 레퍼런스를 썼는지는 `작업.md` 「2. 재료」 경로에서 자동으로 센다. `패턴.md`에 따로 적지 않는다 (병렬 작업에서 같은 파일을 여러 곳이 고치지 않게).
- 사용자가 결과가 좋았다고 하면 그 작업 `작업.md` 머리말 `평가: 좋음`. 목록의 「좋음」에 반영된다.

## 하지 않는 것
- 남의 이미지 · 로고 · 문장을 결과물에 그대로 넣지 않는다.
- 로그인이 필요한 페이지는 사용자에게 캡처를 받는다.
- `references/목록.md`를 손으로 고치지 않는다.
