# 브랜드: 사업 하나 = 폴더 하나

```
brand/
├── 목록.md                 브랜드 목록 + 「기본: <이름>」
└── <브랜드>/
    ├── profile.md          소개 · 타깃 · 말투 · 색 · 폰트 · 음성 ID
    ├── products/<상품>.md   가격 · 일정 · 혜택 · 링크
    ├── assets/
    │   ├── 후기/  후기.md + 캡처      인증/  인증.md + 캡처
    │   ├── 프로필/  로고/  영상소스/  voice/
    │   ├── 폰트/  bgm/  효과음/   + 소재.md (이 브랜드만 쓰는 소재 목록)
    ├── templates/<종류>/    대표 템플릿
    └── 작업목록.md          이 브랜드 작업의 진행 중 · 완성 (자동 생성, 결과물은 works/에)
```

어느 브랜드 일인지 요청에서 알 수 없으면 `brand/목록.md`의 기본 브랜드로 하고, 그렇게 했다고 말한다.

## 새 브랜드
1. `npm run brand -- <이름>` → 폴더 · 양식이 생긴다. 처음 만든 브랜드가 기본.
2. 바로 아래 「같이 채우기」로 `profile.md`를 채운다. `brand/목록.md`의 `- <이름>:` 뒤에 한 줄 소개.
3. 기본 브랜드를 바꾸려면 `npm run brand -- <이름> --default`.

## 같이 채우기 ("프로필 같이 채우자", 자료를 한꺼번에 던질 때)
사용자는 자료를 정리하지 않고 한꺼번에 던져도 된다. **먼저 알아서 나눠 넣고, 그래도 비는 것만 묻는다.**

1. **받은 자료를 나눈다.** 하나씩 보고 제자리로 (파일은 복사, 경로 없는 캡처는 `inbox/`에 넣어 달라고 한 번 요청):
   | 자료 | 가는 곳 |
   |---|---|
   | 소개 글 · 인스타 프로필 · 노션 · 기존 상세페이지 글 | `profile.md` 해당 칸 (상품 내용은 `products/`) |
   | 가격 · 일정 · 커리큘럼이 있는 글 · 페이지 | `products/<상품>.md` (양식 `kit/forms/brand/상품.md`) |
   | 후기 캡처 / 수익 · 성과 캡처 | 「후기 · 인증 저장」 절차 |
   | 본인 사진 · 로고 | `assets/프로필/` · `assets/로고/` |
   | 계속 쓸 영상 · 인서트 | `assets/영상소스/` |
   | 음성 녹음 (1~2분) | `assets/voice/` → `voice` 스킬로 음성 만들기를 제안 |
   | 남의 잘된 콘텐츠 | 브랜드가 아니라 `reference` 스킬 |
   | 어디에도 안 맞는 것 | 넣지 말고 무엇인지 묻는다 |
2. **나눈 결과를 표로 보여 준다** (자료 → 넣은 곳 → 채운 칸).
3. **빈칸만 하나씩 묻는다.** 고르기 쉽게 보기를 준다.
   - 정하는 것(말투 · 색 · 폰트 · 타깃 표현)은 Claude가 후보를 제안해도 된다. 예: "말투는 ① 차분한 존댓말 ② 친구 같은 반말 ③ 고객에게 1인칭으로 말 걸기 중 어느 쪽?", 색은 로고 · 피드를 보고 후보 3개.
   - 사실(가격 · 경력 · 수강생 수 · 성과)은 사용자가 말한 것만 적는다. 모르면 비워 두고 넘어간다. 지어내지 않는다.
   - 한 번에 질문 하나. 사용자가 "나중에"라고 하면 그 칸은 비워 둔다.
4. **다 채운 `profile.md`(와 만든 상품 파일)를 보여 주고** "이대로 저장할까요?"로 끝낸다.

## 이름 바꾸기 ("브랜드1 이름을 ○○로 바꿔줘")
1. `npm run brand -- <지금 이름> --rename <새 이름>` → 폴더 `brand/<이름>/` · `brand/목록.md`(기본 포함) · `profile.md` 제목 · 템플릿 제목 · 지난 작업 `작업.md`(머리말 「브랜드:」와 재료 경로)를 한 번에 바꾼다.
2. 결과(바뀐 작업 수)를 보여 준다. 폴더 이름을 손으로 바꾸지 않는다 — 지난 작업의 경로가 깨진다.

## 후기 · 인증 저장 ("이 후기 저장해줘")
1. 캡처를 `assets/후기/<날짜>-<누구>.png` (인증은 `assets/인증/<날짜>-<무엇>.png`)로 복사한다. 경로 없이 붙여 넣은 캡처면 `inbox/`에 넣어 달라고 한다.
2. 캡처를 읽고 `후기.md`(또는 `인증.md`) 표에 한 줄 추가. 내용 · 숫자는 **캡처에 보이는 그대로**.
3. 사용 동의를 모르면 칸을 비우고 "사용 동의 받았나요?"라고 한 번 묻는다. 「받음」(본인 인증은 「본인」)이 아니면 결과물에 쓰지 않는다.
4. 여러 장이면 한 번에 처리하고 표로 보여 준다.

## 상품 정보 저장
파는 것(상품 · 강의 · 서비스) 하나 = 파일 하나. `kit/forms/brand/상품.md` 양식을 `products/<상품>.md`로 복사해 `{{상품}}`을 이름으로 바꾸고 채운다. 요청에 없는 값은 비워 둔다. 가격 · 일정이 바뀌면 그 파일만 고친다.

## 계속 쓸 자료를 브랜드로 ("브랜드에 저장해줘")
- 기준: 다음 콘텐츠에서도 또 쓰면 브랜드, 이번에만 쓰면 작업 `원본/`.
- 작업 폴더에 있던 것이면 브랜드로 **복사**한다 (작업 쪽은 그대로).
- 사진 → `assets/프로필/`, 로고 → `assets/로고/`, 인서트 · B롤 → `assets/영상소스/`, 음성 학습 녹음 → `assets/voice/`.

## 브랜드 소재 (폰트 · BGM · 효과음)
- 이 브랜드만 쓰는 것은 `assets/폰트` · `assets/bgm` · `assets/효과음`에 넣고 `assets/소재.md` 표에 한 줄 (분위기 · 쓰임 · 길이 · 출처 · 라이선스). 여러 브랜드가 함께 쓰는 무료 소재는 `kit/assets/`(표는 `kit/assets/README.md`).
- 출처 · 라이선스를 모르는 파일은 넣지 않는다.

## 대표 템플릿 ("이걸 대표 템플릿으로 해줘")
1. 결과가 마음에 든 작업 폴더를 확인한다.
2. `npm run brand -- <브랜드> --template works/<종류>/<작업>` → 그 작업의 `편집/`이 `templates/<종류>/`로 복사된다 (렌더 결과 · 음성 · 생성 이미지는 빠진다). 이미 있으면 사용자에게 바꿀지 묻고 `--replace` (이전 것은 `templates/_이전/`에 남는다).
3. 이후 그 브랜드의 같은 종류 새 작업은 이 템플릿에서 시작한다. 모양(레이아웃 · 색 · 글꼴 · 자막 스타일)은 템플릿, 후킹 · 구성은 레퍼런스.

## 하지 않는 것
- 다른 브랜드의 자료를 섞어 쓰지 않는다.
- 후기 · 인증의 숫자 · 표현을 고쳐 적지 않는다.
