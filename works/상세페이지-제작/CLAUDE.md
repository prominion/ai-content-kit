# 상세페이지 (detail-page)

시작은 `detail-page` 스킬. 맨 위 머리말은 `npm run check`가 검사하는 규격이다. (`max_mb`는 빌더 제한을 실측하기 전 임시값)

## 지킬 것
- 가격 · 일정 · 혜택 · 후기 · 수익 인증은 `brand/<브랜드>/products/`와 `brand/<브랜드>/assets/`에 있는 것만 쓴다.
- 결과는 이미지까지 들어간 HTML 한 파일 (이미지 · GIF는 data URI, 내 컴퓨터의 다른 파일을 가리키지 않는다. 웹 폰트 CDN 링크만 예외).
- 실제 인물(본인 포함)은 이미지 생성으로 만들지 않고 `brand/<브랜드>/assets/`의 사진을 쓴다.

## 기본값 (요청이 다르면 요청을 따른다)
- 버전은 기본 하나 (`v1-레퍼런스형`). "하나 더" · "웹툰형으로도"일 때만 새 폴더 (`v2-변형/` · `v3-웹툰형/`).
- 섹션 순서는 레퍼런스를 따르되 강사(판매자) 소개와 후기는 넣는다.
- 모바일 화면 기준으로 먼저 확인한다.
- 글꼴: 브랜드에 정한 것이 없으면 Pretendard.
- 움직이는 요소는 CSS 애니메이션 먼저. 한 장면의 변신 · 정렬처럼 움직임이 메시지면 GIF — `npm run gif`(HyperFrames)로 만든다. GIF 하나 2~3초 · 640폭 · 10fps · 300KB 안팎.
- 휴대폰 폭(375px) 확인은 `npm run shot`.
- 빌더(리드제니 등)에 올릴 때는 `완성/<버전>/빌더용.html` (`<style>`과 본문만).
- 이미지 생성(Higgsfield)은 크레딧을 먼저 확인하고, 결과는 `편집/이미지/`에 쓰임이 드러나는 이름으로 저장.
